`docs/01_customer.md`（3行＋🔮の仮説）を読んで、**`docs/03_spec.md` に要件定義書を書いてください。**

## この要件定義書のゴール

**「その人の業務が、この画面だけで1周回る」**ツールを1つ定義します。
説明ページ（LP）ではありません。**触ると動くツール**です。

「3. 画面」には、**アプリの画面に出るものだけ**を書いてください。
「やらないこと」「仮説」「出口」は**この文書の中だけの話**で、**画面には出しません。**

## 最初に：画面の型を4つ選ぶ

**全員が同じ画面になると、自分の道具に見えません。**
3行から次の4つを決めてください。**選ぶだけです。新しいCSSは書きません。**

### LAYOUT ── 3行目「何が一覧で見られると助かるか」で決まる

| 3行目がこう書かれていたら | LAYOUT | どうなるか |
|---|---|---|
| 「待たせている」「返信していない」「溜まっている」 | `queue` | 古い順に1本の一覧。放置日数が主役 |
| 「どの段階」「どこまで進んだ」「止まっている」 | `stage` | 段階ごとに束ねる。区分が段階になる |
| 「今週」「締切」「期限」「予定」「いつまでに」 | `due` | 期限切れ / 今日・明日 / 今週 / それ以降 に束ねる |

### TONE ── 1行目の相手の業種で決まる

`pine` 教育・サービス・その他／`indigo` 士業・不動産・BtoB／`clay` 建設・工務店・現場／
`sea` 医療・介護・公共／`wine` 飲食・小売・美容

### DENSITY ── 2行目の件数で決まる

`compact` 1日20件以上／`normal` ふつう／`roomy` 1日5件以下で1件が重い

### UNIT ── その仕事の数え方

件 / 名 / 棟 / 台 / 点 / 本 / 現場 など。**「件」で済ませない。**

> ⚠ 3行に手がかりが無ければ、**仮説で選んで 🔮 を付け**、理由を1行書いてください。聞き返さないこと。

## 絶対に守る制約

| 制約 | 理由 |
|---|---|
| **1種類のデータの管理ツールにする** | テンプレートがこの形。メディア・マッチング・決済は今回作らない |
| **画面はテンプレートの3つのまま**（一覧／新規登録／設定） | 既に実装済み。増やすと25分に入らない |
| **データ項目は5つまで** | 入力が面倒だと、その場で試してもらえない |
| **データは `localStorage` に保存** | サーバー・DB・ログインなしで、リロードしても消えない状態を作れる |
| **ログイン・課金・メール送信は作らない** | 25分に入らない。第3回で扱う |
| **新しいライブラリを追加しない** | テンプレートの構成のまま作る |

## 3行のどこが、どこに効くか

顧客の3行と要件定義書は、この対応で繋がっています。**元の情報が濃いほど、ここが具体的になります。**

| 元 | 効く先 |
|---|---|
| 1行目「誰」 | **2. 使う人と場面** ／ 画面の言葉づかい |
| 2行目「何を・頻度・時間」 | **4. データ項目** ／ **5. 操作** ← ここがいちばん効く |
| 3行目「あれば助かる」 | **1. 解くこと** ／ **7. 完成条件** |

2行目に数字（件数・分数）があれば、**データ項目をそこから直接起こしてください**。
例：「1件15分 × 月30件の返信」→ 項目に「問い合わせ日」「返信済みか」、操作に「返信済みにする」。

## 進め方

1. 顧客仮説から**もっともらしく埋める**。空欄で止めない
2. 🔮 が付いていた仮説に依存する項目には、**同じく 🔮 を付ける**
3. 迷ったら**機能を減らす**方向で決める
4. 書き終えたら、**チャットに下の形で要約を出す**

### 要約の出し方（この形を必ず守る）

`docs/03_spec.md` を開かなくても、**この要約だけで「何が作られるか」が分かる**ようにします。

```markdown
## 要件定義書ができました

### 作るもの
（1行。「〜が分かる」「〜が減る」）

### 画面に出るもの
1. …
2. …
3. …

### できる操作（3つまで）
| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | … | … |
| 2 | … | … |
| 3 | … | … |

### 持つデータ
（項目名をカンマ区切りで1行。例：保護者名 / 流入元 / 問い合わせ日 / 返信済みか）

### 今回作らないもの
- …
- …
- …

### できあがりの判定（この3つが満たせたら完成）
- [ ] …

### 次にやること

**`/build` と打ってください。** この設計図どおりに、動くツールを実装します。
```

### 注意

- **「作らないもの」を必ず見せる。**ここが歯止めになります
- **「できあがりの判定」は、見れば誰でもYes/Noが分かる書き方**にする
- 🔮 が付いた仮説に依存する項目には、要約側にも 🔮 を付ける
- 最後の「次にやること」を**必ず入れる**

**この段階ではコードを1行も書かないでください。**
