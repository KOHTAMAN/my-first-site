# DOJO vibeコーディング講座 スターターキット

Claude Code で、**自分の事業のサイトをブラウザだけで本番公開する**ためのひな型です。

- パソコンへのインストールは **0件**（ターミナル・Node.js・VS Code は使いません）
- 使うのはブラウザのタブ3つだけ: **GitHub / Vercel / claude.ai/code**

---

## 全体像

```
 ① GitHub          ② Vercel               ③ claude.ai/code
 テンプレから  ──▶  自分のURLで公開   ◀──  「こう書き換えて」と指示
 自分のリポジトリ    （2分で完了）             ↓
                          ▲               変更案（PR）が出る
                          └──── 自動で再公開 ── マージ
```

やることは **「指示する」「見る」「OKを出す」** の3つだけです。コードは書きません。

---

## 事前に必要なもの

| | 必要なもの | 備考 |
|---|---|---|
| 必須 | **Claude Pro または Max** | Freeプランでは claude.ai/code が使えません |
| 必須 | **GitHubアカウント**（無料） | https://github.com/signup |
| 当日作成 | Vercelアカウント（無料） | GitHubアカウントでログインするだけ |

---

## STEP 1: 自分のリポジトリを作る（3分）

1. このリポジトリのページ上部にある緑色の **`Use this template`** をクリック
2. **`Create a new repository`** を選択
3. リポジトリ名を **英数字とハイフンだけ**で入力（例: `my-first-site`）
   - ⚠️ 日本語や記号を入れると、あとで公開に失敗します
4. **`Public`** を選ぶ
5. **`Create repository`** をクリック

これで、動く状態のひな型があなたのものになりました。

---

## STEP 2: Vercelで公開する（5分）

1. https://vercel.com を開く
2. **`Continue with GitHub`** でログイン
3. **`Add New…` → `Project`**
4. STEP 1 で作ったリポジトリの **`Import`**
5. 設定は**何も触らず** **`Deploy`**
6. 1〜2分待つと、`https://＜あなたのリポジトリ名＞.vercel.app` が発行されます

**この時点で、世界中からアクセスできるサイトのオーナーです。** 中身はまだ仮の文章です。

---

## STEP 3: claude.ai/code とGitHubをつなぐ（3分）

1. https://claude.ai/code を開く
2. GitHubの接続を求められるので、**Claude GitHub App をインストール**
3. ⚠️ **Repository access は「All repositories」を選んでください**
   （「Only select repositories」だと、あとで PR 作成が 403 で失敗します）
4. 入力欄の下にあるリポジトリ選択から、STEP 1 で作ったリポジトリを選ぶ

> あなたのパソコンでは何も動きません。クラウド上にリポジトリのコピーが用意され、そこで作業が行われます。
> だからインストールが要らず、タブを閉じても作業は続きます。

---

## STEP 4: 中身を書き換えてもらう（10分〜）

まず `docs/01_customer.md` を開いて、**誰の何の困りごとを解くのか**を書きます。
（GitHubの画面上で、鉛筆アイコンから直接編集できます）

そのうえで、claude.ai/code に次のように頼みます。

```
docs/01_customer.md を読んで、その内容に合わせて app/page.tsx のトップページを書き換えてください。
条件：見出し1つ、説明3行、CTAボタン1つ／色とフォントは app/globals.css の変数を使う／新しいライブラリは追加しない
```

### 指示には型があります。4つ埋めれば、だいたい通ります

| | 何を | 上の例だと |
|---|---|---|
| **① 対象** | どのファイルを触るのか | `app/page.tsx` |
| **② やること** | 1回の指示に1つだけ | `docs/01_customer.md` の内容に合わせて書き換える |
| **③ 条件** | 守ってほしいこと | 見出し1つ・説明3行・CTAボタン1つ |
| **④ 禁止** | やらないでほしいこと | 新しいライブラリを追加しない |

> 新人に仕事を頼むときと同じです。違うのは、**やり直しがタダ**なことだけ。
> 「かっこよくして」では、何も決まりません。

### 仕上げは3回の往復で。追加 → 修正 → 削除 の順

1. **追加** — 足りない要素を1つ入れる
2. **修正** — 文言と色を直す
3. **削除** — 不要な部分を消す

> 削除を最後にするのは、消してから足すと**同じものをまた作らせる**ことになるから。
> 3回とも、それぞれPRを分けて出してください。

そのあとの流れ:

1. 作業が終わると `+42 -18` のような**差分**が出る → クリックして中身を確認
2. 直したい行があれば、その行を選んでコメントを書く（次のメッセージと一緒に送られます）
3. 納得したら **`Create PR`**
4. GitHubで **`Merge pull request`**
5. 数分後、あなたの公開URLをリロードすると中身が変わっています

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| Vercelのビルドが失敗する | リポジトリ名に日本語・記号が入っていないか確認（英数字とハイフンのみ） |
| **Create PR で 403**（`Resource not accessible by integration`） | Claude GitHub App が**インストールされていません**。https://github.com/apps/claude/installations/new → **All repositories** → Install<br>※「Authorized GitHub Apps」タブに出ていても書き込み権限はありません（別物） |
| claude.ai/code にリポジトリが出てこない | 同上。https://github.com/apps/claude/installations/new で All repositories を選ぶ |
| Claudeが延々と動き続ける | いったん止めて、指示を小さく分けて出し直す |
| マージしたのにサイトが変わらない | Vercelの `Deployments` タブでビルド中でないか確認。終わっていたらブラウザをスーパーリロード |
| `Session creation failed` と出る | 1分待って、もう一度送る |

## 何が入っているか

```
.
├─ CLAUDE.md              ← Claude Code が毎回読む指示書（一番大事）
├─ app/
│  ├─ layout.tsx          ← 全ページ共通の枠。サイトのタイトル・説明
│  ├─ page.tsx            ← トップページの中身
│  └─ globals.css         ← 色・余白・文字サイズの定義
├─ docs/
│  ├─ 01_customer.md      ← 誰の何の課題か（ここから作る）
│  └─ 02_onepager.md      ← 何を作るかの1枚仕様
├─ samples/               ← 記入例（CLAUDE.md / 01_customer / 02_onepager の記入済み版）
└─ .claude/commands/      ← よく使う指示のショートカット
```

### 使えるショートカット（claude.ai/code の入力欄で打つ）

| コマンド | 何が起きるか |
|---|---|
| `/customer` | 顧客と課題を1問ずつ聞かれ、`docs/01_customer.md` が埋まる |
| **`/gtm`** | **出口の3点（誰が払う・どう届く・受け取れる）を1問ずつ詰める。作る前に通す** |
| **`/spec`** | **顧客仮説から要件定義書（`docs/03_spec.md`）を作る。まだコードは変えない** |
| **`/build`** | **要件定義書から、本番URLで動くツールを実装する** |
| `/plan` | 小さな追加変更の前に1枚仕様を作る |
| `/check` | 公開前チェック（秘密情報・根拠のない数字・スマホ表示・リンク切れ） |

### このコマンドを、他のプロジェクトでも使うには

**スラッシュコマンドの正体は `.claude/commands/○○.md` というただのテキストファイルです。**
中身は日本語の指示文にすぎません。**このリポジトリの外では使えません。**

| # | やり方 |
|---|---|
| ① | **`.claude/commands/` をフォルダごとコピー**する |
| ② | **Claudeに作らせる**：「`.claude/commands/kickoff.md` を作って。中身は〜」 |
| ③ | **コマンドを使わず、`.claude/commands/kickoff.md` の中身をそのまま貼る** |

②が分かると、**よく使う指示を自分でコマンド化できます。**2回目以降のプロジェクトが毎回速くなります。

## 大事なこと

**`CLAUDE.md` の 1〜3章を埋めてください。**

| 章 | 何を書くか | 埋めないとどうなるか |
|---|---|---|
| **1. 誰のためか** | 実名で挙げられる顧客。属性ではなく人 | 「それっぽいもの」ができる |
| **2. 解く課題** | 今どうやっているか。何に時間と費用を使っているか | 一般論の文言になる |
| **3. やらないこと** | 今回入れない機能 | **良かれと思って機能を足される** |

📄 埋まっているとどう見えるかは [`samples/CLAUDE.sample.md`](samples/CLAUDE.sample.md) を見てください。
