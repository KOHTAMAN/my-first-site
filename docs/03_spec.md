# 要件定義書

> `/spec` が `docs/01_customer.md`（3行＋確認済みの事実＋🔮の仮説）から組み立てたものです。
> 題材は「子連れのお出かけスポット候補の管理」。

---

## 0. 画面の型

- **LAYOUT: `stage`**
  区分ごとに束ねる型を選ぶ。この題材の区分は「進捗の段階」ではなく **天気**。明日の天気が分かっている状態で開くので、**「雨の日」の束だけ見れば候補が出そろう**形がいちばん速い。`queue`（古い順）だと放置日数が主役になってしまい、候補を貯めておくこのツールとは合わない。
- **TONE: `pine`** 🔮
  1行目に業種がない（家庭で使う道具）ため、教育・サービス・その他の `pine` を仮に選んだ。夜に開くので、硬すぎず落ち着いた色みが合うと思われる。
  → 確かめ方：「この画面の色、寝る前に見て疲れない？」
- **DENSITY: `roomy`**
  出かけ先を検討するのは月4〜6回（確認済み）。1件が「休みの1日をまるごと使う外出」で重く、スマホで見るため、余裕のある表示にする。
- **UNIT: `か所`**
  遊び場の数え方は「3件の候補」より「3か所の候補」が自然。「件」だと業務書類の感触になる。

**CATEGORIES（区分＝天気）**: `["晴れの日", "雨の日", "どちらでも", "期間限定"]`
3行目の「対象日の天気と、天気に合わせたおすすめのスポット」をそのまま区分にした。天気予報は取りに行かず、**スポット側に「どの天気向きか」を持たせる**ことで同じ結果にする。

## 1. このツールが解くこと

明日の天気（晴れ／雨）に合う遊び場の候補が、**費用と行き方つきで3分以内に出そろう。**
その結果、休みの前日の下調べ45分がなくなり、**その分だけ早く寝られる。**

## 2. 使う人と、使う場面

- **使う人**: 夫（登録・更新する人）と、妻（3歳と1歳を育てる専業主婦。見て決める人）。同じ1つの画面を2人で見る。
- **いつ開くか**:
  - 夫 … 🔮 Instagram で良さそうな投稿を見つけて深掘りした直後、その場で1か所ぶん登録する。
    → 確かめ方：「良さそうな場所を見つけたとき、その場で登録できそう？後でまとめて？」
  - 妻 … **休みの前日の夜、子供を寝かしつけたあと**（確認済み。ここまでは30〜60分かかっていた時間）。
- **開いて最初にしたいこと**: 明日の天気に合う束を見て、費用が合う1か所を選ぶ。

## 3. 画面（テンプレートの3画面をそのまま使う）

一覧画面に、上から順にこれだけが出る。

1. **今の状況の数字** — `[ ◯ ]まだ行っていない` `[ ◯ ]雨の日でもOK` `[ ◯ ]全か所`
2. **検索と絞り込み** — 名前で検索する欄／天気の区分（晴れの日・雨の日・どちらでも・期間限定・全部）／状態（まだ・行った・全部）
3. **天気の区分ごとに束ねた一覧** — 束の見出しに「雨の日　3か所」。1行に **スポット名 ／ 行き方・所要 ／ 費用のめやす ／ 行った日** と、`[行った]` `[編集]` `[削除]`
4. **0か所のときの表示** — 「まだ候補がありません。右上の『新規登録』から1か所目を登録してください。」

> 画面に出すのはここまで。**「やらないこと」「🔮の仮説」「出口の3点」「競合」は画面に出さない**（`DESIGN.md` 0章）。

## 4. データ項目

入力するのは5つ。登録日は入力せず、追加したときに自動で入る。

| 項目 | 型 | 必須 | 例 |
|---|---|---|---|
| スポット名 | 文字列 | ○ | 川沿いの大型公園（ふわふわドームあり） |
| 天気の区分 | 晴れの日 / 雨の日 / どちらでも / 期間限定 | ○ | 雨の日 |
| 行き方・所要 | 文字列 | － | 車25分・駐車場あり（無料） |
| 費用のめやす | 数値（円・家族4人ぶん） | ○ | 1200 |
| 行ったか | true / false | ○ | false |

- 🔮 費用は「家族4人ぶんの入場料・駐車場代の合計」の目安として入れる。3行目の「家族構成に合わせた費用」は、家族が固定（大人2・子2）なので**1つの数字で足りる**と判断した。
  → 確かめ方：「費用って、1人いくらより家族で合計いくらのほうが分かりやすい？」
- 子供の氏名・写真・住所は**持たない**（`CLAUDE.md` 8章）。

## 5. 操作（3つまで）

| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | 候補を追加する | 「新規登録」で5項目を入れると、今日の日付で「まだ行っていない」に入る |
| 2 | 天気で絞り込む | 「雨の日」を選ぶと、雨でも遊べる候補だけが残る（検索欄で名前からも絞れる） |
| 3 | 「行った」にする | その1か所が「まだ行っていない」から消え、行った日が記録される（データは残り、「行った」で見返せる） |

## 6. やらないこと

`CLAUDE.md` 3章の3つ＋今回の範囲外。

- **天気予報の自動取得（天気API連携）** — 天気は区分として手で持つ。明日の天気はスマホで見れば分かる
- **イベント情報の自動収集・外部サイトからの取り込み** — 期間限定イベントは見つけたときに手で1か所登録する
- **妻からの入力・口コミ投稿・地図やルート検索** — 今回は夫が登録・更新する1人運用にする
- 地図表示・経路検索・混雑状況の取得
- ログイン、複数端末での共有（第3回で扱う）
- 決済・課金・メール送信・通知

## 7. 完成条件

- [ ] 「雨の日」を選ぶと、**雨でも遊べる候補だけ**が天気の束ごとに表示される
- [ ] 「行った」を押すと、その1か所が「まだ行っていない」から消える
- [ ] **リロードしてもデータが残っている**

## 8. 保存方法

`localStorage` に1つのキーで保存する。キー名: `odekake-spots`

※ 端末ごとの保存です。**夫の端末と妻の端末での共有は第3回**で扱います。
